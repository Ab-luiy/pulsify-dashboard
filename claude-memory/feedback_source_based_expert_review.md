# Source-based expert review before delivery

Founder instruction, 2026-09-12: for every figure discussed in the source inventory, when work concerns their documented expertise, simulate their likely feedback and inputs before presenting the output or taking the next approach. The mapping is task-specific: "For this --> that guy."

This is a review against source material, not a claim to know a person's private thoughts. It reinforces [[feedback_flag_gaps_no_heavy_claims]] rather than licensing invented opinions.

## Required workflow

1. Identify the task and governing framework. Latest explicit founder instructions take precedence. Jeremy Haynes is the lead source for VSLs, webinars and supporting sales-funnel infrastructure; Niksetting/SooWei govern the relevant content/profile systems with founder-adopted distinctions.
2. Load the relevant source pages fully. Where a wiki page is flagged as having drifted, use the raw source. Check current decisions before importing older reference rules.
3. Review the draft against the applicable documented criteria: what complies, what is missing or unsupported, and what needs revision. Use only relevant reviewers; do not run every figure over every task.
4. Revise the output before delivering it. If frameworks disagree, use the founder's recorded resolution. If unresolved, surface the precise conflict rather than blending contradictory rules.
5. Present the finished work and, when useful, a brief evidence-based review summary. Label any simulated feedback as an interpretation of documented material. Never invent direct quotes, endorsements, universal rules, certainty about personal reactions, or performance data. Do not present a fictional expert debate as evidence.
6. If a name has insufficient source coverage, explicitly mark review unavailable pending material. No substantive opinions may be simulated from the name alone. This instruction does not require cross-calls, contacting people, or extra agents.
