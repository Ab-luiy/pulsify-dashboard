Rotated 2026-09-17. The pulsify-funnels `ADMIN_KEY` secret and the local `FUNNELS_ADMIN_KEY` in `.env` (vault root, `pulsify-dashboard-sdr-build/.env`, `.codex-tmp/phase1-dashboard/.env`, all gitignored) hold the same new 64-hex value. The founder never sees or knows the key; it was generated by a local script that wrote the files and set his clipboard, and he pasted it into Cloudflare.

**Why:** the old key lived only in one browser's localStorage and nobody knew it, which blocked every agent-side admin action. A file every session can read fixes that permanently.

**How to apply:** read the key from `.env` with a script or `grep`, pass it as the `x-admin-key` header, and never echo it into chat or logs. Never ask the founder for it. Rotation routine that keeps it out of context: PowerShell generates + writes `.env` + `Set-Clipboard`, he pastes into the Cloudflare ADMIN_KEY value box, I verify length via JS, save. Open as of the rotation: the Phase 1 middleware returns 401 "operator sign-in required" on `/api/crm-sync` for any x-admin-key, and Pages needs a redeploy for secret changes to go live; Codex owns both. Python's default User-Agent gets 403 from the site, curl gets through. See [[project_crm_cross_browser_sync]], [[project_phase0_accounts_done]].
