When auditing the IG inbox or building prospect lists, the user wants speed and signal, not exhaustive per-thread analysis.

- Do NOT do heavy per-thread work (opening every thread for deep notes). Scroll + scrape names/handles fast. Handles only exist when a thread is opened — state that constraint, don't grind 100+ opens.
- Strip everything not a real pitch/outreach target: peers, friends, spam, deactivated accounts, failed sends, and existing/ex-clients. "Do not log useless data we won't use."
- Nicholas / @niicksfx is a past/active client, not a cold lead — nurture, never pitch.
- Deliverable lives in `dashboard.html`: the CRM must be an expanded, real data table (excel-like — searchable, filterable, columns incl. DMs sent), not a thin list. "Expand more on the CRM, don't just make it like that."

**Why:** the user runs lean and fast (see speed_is_the_motto). The Apr 2026 mass blast (~100 identical voice-note+Loom DMs, ~4% reply) is the anti-pattern; the plan is to retarget those same leads leading with a custom value asset per the Pulse System playbook.

**How to apply:** for any lead-list / inbox task, default to a fast scrape → filter to actionable only → land it as structured, filterable data in the dashboard. Don't produce long per-prospect prose or keep peers/noise "for completeness."
