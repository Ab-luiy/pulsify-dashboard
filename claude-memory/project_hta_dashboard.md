`dashboard-v3.html` ("Pulsify — HTA Dashboard") is not a one-off operator tool. It is the **pillar/proof** Pulsify will build on to ship a client-facing CRM/dashboard product ("send half to me, half to clients").

**Why:** Pulsify is an agency; clients need their own tracked dashboard. V3 is the foundation that gets extended per client (agency-specific extra sections expected later).

**How to apply:**
- Treat every change to V3 as product work, not throwaway. Quality bar is explicitly "better than Airtable / better than high-level dashboards" — million-dollar-CRM professional, premium, dynamic, never cringe.
- Client view requirement (not built yet, do NOT build until asked): clients must see **where they are lacking** — weak numbers, conversion leaks, what to improve — not just vanity stats. A client layout that surfaces gaps + next actions is the eventual goal.
- File lineage / failsafes: `dashboard.html` (clean v1), `dashboard-v2.html` (Codex expanded; failsafe), `dashboard-v3.html` (active HTA build). Always keep a working failsafe before large reworks.
- As of 2026-05-17 the user is in "context-giving" mode on client mode — deferred, not approved. Wait for explicit go.
