Push API

Send leads, messages, metrics and payments into Pulsify from Zapier, Make, n8n or your own code. One endpoint, one key, idempotent by design.

Endpoint

POST https://pulsify-ai.com/api/v1/ingest
Content-Type: application/json
X-API-Key: pk_your_key

Create a key under Integrations, Push API keys. The key is shown once. Authorization: Bearer pk_your_key also works. The workspace is inferred from the key, so no client id is needed in the body.

Body

{
  "kind": "lead" | "message" | "metric" | "payment",
  "external_id": "optional, used for idempotency",
  "data": { ... }
}

Kinds

KindRequiredOptionalWhat happens
leadone of name, handle, emailsource, notes, tags[] (max 20), stageAppears in the pipeline. Operator-scope leads land in Lead Studio immediately. Emits lead.created.
messagehandle, direction (inbound or outbound), textts, channelStored against the conversation. Emits conversation.new_message.
metricsource, metric, valuets, dims (max 20 keys)One point in the metrics store. Same source, metric, ts and dims never duplicate.
paymentamount (major units) or amount_cents, referencecurrency, customer_email, customer_name, occurred_at, noteRecorded and matched to a lead. Exact email match confirms automatically, anything else is suggested for review. Emits payment.received.

Responses

CodeMeaning
201Created. Body has id and kind.
200Duplicate. Same external_id or reference seen before. Body has duplicate: true.
400Body is not valid JSON.
401Missing, revoked or unknown key.
413Body over 1 MB.
422Validation failed. Body has error.
429Over 30 requests per minute for this key. Retry after 60 seconds.

Zapier

Use Webhooks by Zapier, action POST. Payload type JSON. Header X-API-Key. Map fields into data. Example body for a new Typeform application:

{
  "kind": "lead",
  "external_id": "typeform:{{response_id}}",
  "data": {
    "name": "{{name}}",
    "email": "{{email}}",
    "handle": "{{instagram}}",
    "source": "typeform",
    "stage": "Applied"
  }
}

n8n

HTTP Request node, method POST, JSON body, header X-API-Key. For a Stripe charge from an n8n trigger:

{
  "kind": "payment",
  "data": {
    "amount_cents": {{ $json.amount }},
    "currency": "{{ $json.currency }}",
    "reference": "{{ $json.id }}",
    "customer_email": "{{ $json.billing_details.email }}",
    "customer_name": "{{ $json.billing_details.name }}",
    "occurred_at": "{{ $json.created_iso }}"
  }
}

curl

curl -X POST https://pulsify-ai.com/api/v1/ingest \
  -H "Content-Type: application/json" \
  -H "X-API-Key: pk_your_key" \
  -d '{"kind":"lead","external_id":"ig:someone","data":{"handle":"someone","source":"manual"}}'

Outbound webhooks

The reverse direction. Add an HTTPS endpoint under Integrations, Outbound webhooks, pick events, and store the signing secret shown once. Each delivery carries:

X-Pulsify-Signature:   hex HMAC-SHA256 of the raw body with your secret
X-Pulsify-Event:       event name, for example payment.matched
X-Pulsify-Delivery-Id: unique per delivery, use it to de-duplicate

Body is { id, event, created_at, data }. Return any 2xx within 10 seconds. Pulsify retries three times with 1, 2 and 4 second backoff. Test sends include "_isTest": true in data. Verify the signature before trusting a payload.
