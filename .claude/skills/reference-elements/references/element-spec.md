# Element construction record

Use a short record for an isolated graphic. Use the existing vault scene/job schema when producing a full slide or set; this worksheet is not a replacement renderer schema.

## Evidence and intent

Record the reference path/ID, inspected crop, complete-slide context, and the element's job. Name the mode: reference study, production adaptation, or new element. Separate visible details from estimates and unknowns.

## Component description

| Field | Useful content |
|---|---|
| Identity | Stable ID and recognizable component name |
| Meaning | What the viewer should understand; why this visual form fits |
| Canvas | Destination width/height, background, and intended display size |
| Geometry | Normalized x/y/width/height; silhouette; internal padding and alignments |
| Type | Exact copy/line breaks; font file or disclosed substitute; size/weight/tracking/line height |
| Material | Role of fill, opacity, border/stroke, shadow, highlight, or texture |
| Parts | Named text blocks, shapes, assets, nodes, edges, and annotations |
| Layers | Back-to-front order; clipping/masks; essential foreground labels |
| Assets | Actual paths/IDs and source context; distinguish screenshots from illustrative UI |
| Data | Conceptual, captured proof, or measured; records/units/window if measured |
| Editability | SVG text/groups, HTML/CSS components, native editor objects, or flattened regions |
| Acceptance | Reference-specific visible relationships to preserve |
| Unknowns | Missing font/source layer/hidden text; chosen approximation or required input |

Not every field needs a separate paragraph. Keep exact values where measured; mark estimated ratios as estimates. A reusable element should expose meaningful values such as labels, stage count, palette, and dimensions rather than burying them in drawing commands.

## Source-backed starting patterns

Find the original anchors and recipes in `wiki/content-engine/reference-replication-profile.json` and visually inspect the selected source before using them.

- **Categorical funnel** (`three-platform-funnels`, K1-4): preserve stage silhouette, named roles, branching inputs and convergence. Band width communicates category hierarchy unless actual data supports proportional values.
- **Route map** (`hybrid-route-map`, K1-6): nodes have meaningful labels; connectors identify sources and endpoints. Route around labels and preserve branches.
- **Paired artifacts** (`paired-work-states`, G1-4/6): the two objects represent distinct outputs/states, with specific internal construction and labels.
- **Report/task artifacts** (`feature-three-artifacts`, G1-2/3/5/8): reproduce the meaningful interior, visual density, and its relationship to the title/photo.
- **Source-detail lens** (`source-detail-lens`, Story S2): magnify the exact source region, retaining its evidence context and a clear return connector.
- **Phone taxonomy** (`white-phone-taxonomy`, NT-2–8): preserve phone silhouette, information chips, axis/ordinal roles, and the source's flexible collage arrangement.
- **Rear display type** (`outlined-name-behind-subject`, G1-1/G2-1): align the subject restore with the photo; keep the intended text mass and essential foreground message readable.

These are retrieval hints, not fixed templates. Use only a pattern that matches the current component and brief. Sources can contain readable defects; record any correction instead of silently calling the result identical.

## Comparison note

For the rendered result, name the most important preserved relationship and any visible deviation. Record which size(s) and intersections were inspected. Keep unresolved defects explicit; do not replace comparison with adjectives such as premium or polished.
