# MVP plan: first paid client on the portal

Goal: a client signs, logs in, answers the guided questions, and gets reviewed output they can use, with no empty screens and no hand-wiring from us. Payments are out of scope: the founder logs them by hand. UI is done; this plan is about what drives it.

Audit basis (2026-10-02, code read, not a signed-in click-through): portal nav (14 items), 97 API files, 5 AI callers, provisioning, checklist, dashboard feeds.

## What is real vs. what is hand-fed

- Real and driven: onboarding -> client brain, voice note, story sequences (learning loop), YouTube ideation/title/build, review gate, media library, leads, performance logging, cash by video.
- Hand-fed only: Plans, To-dos, Team (operator writes JSON into client_dashboard_content). Nothing fills them on provision, so a new client sees three "not loaded yet" screens.
- Content (client): reads content_items. Only the operator or a data import writes it; approved YouTube and sequence packages never land there.
- Copywriter: still on Cloudflare Llama with the 30/day cap. The founder rejected both.
- Delivery automations exist operator-side (pre-call brief on booking, Fathom call import, Monday weekly-report draft). The earlier note saying pre-call briefs were not built was wrong; the client-facing Sales Co-pilot and comment triage are still not built.

## Duplicates and repeats found

Verified:
- Five separate LLM callers: _shared/anthropic.js (the good one), _shared/llm.js (delivery, ask), dashboard-generate.js, generate.js, studio-carousels.js, each with its own Gemini or Anthropic fetch. The Copywriter is a sixth path (env.AI).
- The client portal has three "library of what we made" screens: Content, Instagram projects, YouTube projects.
- Legacy static pages still shipped beside the Next app: client.html, portal.html, admin.html, settings.html, campaigns.html, integrations.html, portal/legacy.js, phase1.js, studio-app.js, workspace-shell.js.

Candidates to verify before cutting (not confirmed):
- Client portal: Tracker vs Performance vs Payments overlap; Team is empty until a sales team exists.
- Operator: lead flow spread over Today, Queue, Outreach tracker, CRM, Inbox, Leads; Integrations vs Payments.
- Backend: client-dashboard / workspace-summary / client-data; client-context / client-brain-export; studio-sequences / sequence-variants / metrics-sequences.

## Plan

Phase 1, client one cannot be blocked (build first)
1. Live provisioning run to an inbox the founder names: welcome email, setup link, onboarding, checklist.
2. Day-1 checklist: voice note -> who you sell to -> first YouTube video (ideation) -> review -> ship. Connect-payments becomes optional.
3. Seed on provision: Plans (week by week from offer v1), To-dos (first-week deliverables), Team (founder as lead). No empty screens.
4. Approved packages write to content_items so client Content shows what is in production and shipped.

Phase 2, one engine (drivers)
5. Collapse all LLM calls into _shared/anthropic.js, one switch, manual copy-paste fallback everywhere. The Copywriter moves onto it and the 30/day cap goes.
6. Fix the gaps that weaken output: YouTube shoot sheet and editing standard (vault gap), BOF-video ruling.

Phase 3, cut duplicates (after the verify pass)
7. One library in the portal. Delete the legacy static pages once confirmed unreachable. Merge or hide Tracker and Team if redundant.

Phase 4, a real signed-in test
8. Sign in as a demo client and click every route end to end; fix what breaks.

Deferred: carousels, reels, landing builder, Miro builder, webinars, walkthrough video, Sales Co-pilot, comment triage.
