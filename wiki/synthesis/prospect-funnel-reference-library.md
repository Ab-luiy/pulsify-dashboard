# Prospect funnel reference library

Pulsify builds a real landing-page design for a prospect before asking for a
call. Mason Bowstead supplies the default conversion skeleton. Luke Alexander
supplies the AI-native visual layer when the prospect's category calls for it.
Charlie Morgan, Grant Garcia, and Ayman Arab supply specific structural mechanics.

## Why this matters for Pulsify

This turns the funnel pillar into the acquisition mechanism. The free page is not
an audit or a promise to do work later. It is a working preview of what Pulsify
would install. Each follow-up adds the next part of the same system: landing page,
voice-matched VSL, Typeform, then the next useful conversion asset.

The prospect experiences the Pulse System before hearing a pitch. Information is
not the bottleneck. Shipped implementation is the proof.

## Core mechanics

### The design hierarchy

**Mason first.** Default to the clean white/off-white page, heavy Inter Tight
headline, narrow centered column, one blue CTA, large VSL, application directly
under it, and real screenshot proof. The page should feel expensive because it is
controlled, not because it is decorated.

**Luke second.** For AI, automation, software, and technology-led prospects, keep
Mason's conversion path and add Luke's faint grid, monochrome technical identity,
editorial headline treatment, named-system cards, agent or workflow diagrams, and
interface-style product visuals. AI should be visible in the design without
turning the page into neon tool hype.

**Charlie for sophisticated B2B.** Pull the qualifier badge, mechanism-led
headline, adjacent risk reversal, and immediate VSL-to-calendar flow. Use the
black-and-gold skin only when the prospect already has mature proof and a premium
B2B market.

**Grant for compression and proof volume.** Pull the short hero, giant VSL, direct
application instruction, and screenshot wall. Do not copy beginner-income claims.

**Ayman for long-form proof architecture.** Pull stage-specific case studies,
before/after blocks, the full delivery breakdown, and context-specific CTA labels.
Only build this length when the prospect has enough proof and offer detail.

### The default free landing page

The first version sent in outreach should contain:

1. A prospect-specific eyebrow that qualifies the buyer.
2. One mechanism-led headline in the prospect's language.
3. A short subhead that names the result and removes ambiguity.
4. One primary CTA.
5. A 16:9 VSL placeholder with the prospect's name and offer.
6. A serious application preview directly under the VSL.
7. Two or three real proof placeholders labeled for the exact assets needed.
8. A short offer or mechanism breakdown only if the research supports it.
9. One closing CTA.

The prospect should be able to replace placeholders and launch. A pretty homepage
that cannot accept a VSL, qualify a lead, or book a call is not the deliverable.

### The consecutive value sequence

Each message carries one finished asset. The assets compound into one coherent
funnel.

1. **Landing page design:** "I went through your site and rebuilt the conversion
   page for your offer. Here is the live version."
2. **Voice-matched VSL script:** "I kept working on it. The page needs a VSL, so I
   wrote the script from your videos using your language and mechanism."
3. **Typeform:** "The VSL needs somewhere to send qualified people. I built the
   application and the qualification logic."
4. **Next diagnosed asset:** pre-call email sequence, confirmation page, ad
   scripts, content angles, or a tracking map based on the actual remaining leak.

No follow-up says "just checking in." The follow-up is another useful thing.
There is still one asset and one link per message. The difference is that Pulsify
keeps building instead of treating the first free asset as the entire campaign.

## How Pulsify uses this

For every qualified lead with a weak or missing conversion page:

- Research the creator's voice, offer, mechanism, proof, and buyer before design.
- Build from Mason's skeleton.
- Add Luke's visual layer only when AI or technology is genuinely part of the
  creator's market identity.
- Use the other references to solve a specific structural problem.
- Keep every claim inside the proof available from the prospect's public material.
- Preserve the page as a working handoff, then build the VSL and Typeform as the
  next follow-ups.

This is the default client-acquisition motion for Pulsify. Other asset-first
routes remain available when the prospect has no offer or when a landing page
would diagnose the wrong wound.

## Open questions / gaps

- The standard cadence between each asset follow-up is not locked.
- The handoff format for live pages still needs one canonical hosting method.
- Proof placeholders must be replaced by the prospect's real screenshots and
  videos before any page becomes production-ready.
- The current Ayman page is a long-form application page with no detected VSL
  embed. Re-check it before treating it as a VSL wrapper.
